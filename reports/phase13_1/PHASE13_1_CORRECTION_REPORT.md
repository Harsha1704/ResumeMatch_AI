## 3. Baseline Provenance Audit: Forensic Investigation

A central question in Phase 13 was whether the "36.8% Production Baseline" matched the deployed checkpoint `models/best_model.joblib`.

### Forensic Audit Evidence

| Evaluation Checkpoint | Evaluated Split | Accuracy | Good Fit Recall | Status / Origin |
| :--- | :--- | :--- | :--- | :--- |
| `models/best_model.joblib` | `dual_unseen_val_v1.parquet` ($N=296$) | **73.99%** (219/296) | **92.47%** (86/93) | **CONTAMINATED / LEAKAGE** |
| `exp1_clean_dual_unseen_baseline_logreg` | `dual_unseen_val_v1.parquet` ($N=296$) | **36.82%** (109/296) | **15.05%** (14/93) | **UNCONTAMINATED RETRAINED BASELINE** |

### Root Cause
1. `models/best_model.joblib` was trained in Phase 3 under Evaluation Protocol A (Job-Disjoint split). In Protocol A, candidate resumes were randomly distributed between train and val.
2. Forensic cross-referencing revealed that **91 out of 91 unique candidates in Dual-Unseen validation (100%) were present in the training set of `best_model.joblib` (`train_sub_A`)**.
3. Therefore, evaluating `best_model.joblib` on Dual-Unseen validation results in massive candidate leakage, yielding an artificial 73.99% accuracy.
4. The historical 36.82% baseline used across Phase 12F2 and Phase 13 was generated by an in-memory scratch model trained strictly on `dual_unseen_train_v1.parquet` (clean), and preserved in `experiments/phase12f2/predictions/phase12f2_dual_unseen_val_predictions.csv` (`pred_baseline_logreg`).
5. **Conclusion:** The 36.82% baseline is the only scientifically legitimate, uncontaminated comparator for Dual-Unseen validation.

## 5. Statistical Significance Reconciliation

To resolve conflicting statistical findings under crossed clustering (91 candidate clusters, 52 job clusters, $N=296$), we cross-checked three independent statistical methodologies comparing Model 5 against the Clean Baseline:

### Statistical Test Results (Model 5 vs Clean Baseline)

| Method / Framework | Test Statistic | p-value / 95% CI | Zero Crosses? | Statistical Decision |
| :--- | :--- | :--- | :--- | :--- |
| **McNemar Exact Test** | $n_{01}=43, n_{10}=22$ ($N_{\text{disc}}=65$) | **$p = 0.0125$** | N/A | **SIGNIFICANT** ($\alpha < 0.05$) |
| **CGM (2011) Two-Way CRVE** | $\hat{\Delta} = +7.09\text{ pp}, \text{SE} = 3.32\text{ pp}$ | **$[+0.60\text{ pp}, +13.59\text{ pp}]$** | **NO** | **SIGNIFICANT** |
| **Owen (2007) Pigeonhole Bootstrap (Accuracy)** | $\bar{\Delta} = +7.00\text{ pp}, \text{SE} = 4.93\text{ pp}$ | **$[-2.98\text{ pp}, +16.58\text{ pp}]$** | **YES** | **NON-SIGNIFICANT** |
| **Owen (2007) Pigeonhole Bootstrap (Macro F1)** | $\bar{\Delta} = +0.0899$ | **$[+0.0014, +0.1798]$** | **NO** | **SIGNIFICANT** |
| **Owen (2007) Pigeonhole Bootstrap (Good Fit Recall)** | $\bar{\Delta} = +11.63\text{ pp}$ | **$[0.00\text{ pp}, +27.94\text{ pp}]$** | **BORDERLINE** | **DIRECTIONAL** |

### Statistical Synthesis & Reconciliation
1. **Paired Dominance:** Under the paired exact McNemar test, Model 5 achieves 43 wins vs 22 losses on discordant pairs ($p = 0.0125$), demonstrating significant directional superiority.
2. **Analytical Clustering (CGM Sandwich):** Accounting for candidate and job clustering analytically, design effect $\text{DEFF} = 1.5119$ ($N_{\text{eff}} = 195.8$). The 95% confidence interval $[+0.60\text{ pp}, +13.59\text{ pp}]$ strictly excludes zero.
3. **Resampling Dispersion (Owen Pigeonhole):** The 2-way Pigeonhole bootstrap resamples both candidates and jobs with replacement, introducing compound binomial cluster variance. Under this extreme dispersion test, the accuracy 95% CI crosses zero ($[-2.98\text{ pp}, +16.58\text{ pp}]$), though Macro F1 strictly excludes zero ($[+0.0014, +0.1798]$).
4. **Conclusion:** Improvement is statistically defensible under paired and analytical CRVE models, but conditional on cluster dispersion tolerance. Gate 3 is properly marked **CONDITIONAL**.

## 6. Probability Calibration Audit

### Mathematical Correction
The standard multiclass Brier score is defined as:
$$\text{BS}_{\text{raw}} = \frac{1}{N} \sum_{i=1}^N \sum_{k=1}^K (p_{ik} - y_{ik})^2$$
For $K=3$ mutually exclusive classes, the maximum possible value occurs when predicting certainty for the wrong class:
$$(1 - 0)^2 + (0 - 0)^2 + (0 - 1)^2 = 1 + 0 + 1 = 2.0$$
The normalized Brier score must divide by $2.0$, **not $3.0$**:
$$\text{BS}_{\text{norm}} = \frac{\text{BS}_{\text{raw}}}{2.0} \in [0, 1]$$

### Probability Column Permutation Bug Resolution
During Phase 13, `predict_proba` was indexed with `CLASS_TO_IDX = {"No Fit": 0, "Potential Fit": 1, "Good Fit": 2}`. However, `LogisticRegression.classes_` sorts classes alphabetically: `['Good Fit', 'No Fit', 'Potential Fit']`.
This inverted P(Good Fit) and P(No Fit) in the exported CSV.
Upon correctly restoring class alignment:

| Model Architecture | Raw Brier Score | Normalized Brier (Raw / 2.0) | Expected Calibration Error (ECE) |
| :--- | :--- | :--- | :--- |
| **Model 1: Clean Baseline (Proxy)** | 0.7454 | 0.3727 | 0.2318 |
| **Model 2: Raw SBERT Baseline** | 0.7056 | 0.3528 | 0.1682 |
| **Model 4: Skill-Aware Matching** | 0.7503 | 0.3751 | 0.2137 |
| **Model 5: Fusion Challenger** | **0.7022** | **0.3511** | **0.1896** |

### Calibration Assessment
- Model 5 Normalized Brier Score is **0.3511**, which is essentially right at the 0.35 threshold.
- ECE is **0.1896**, slightly above the 0.15 threshold.
- Model 5 is better calibrated than the Clean Baseline (0.3511 vs 0.3727) and matches Raw SBERT (0.3511 vs 0.3528).
- Because ECE exceeds 0.15, Gate 7 is designated **CONDITIONAL** (recommending post-hoc temperature scaling).

## 9. Forward-Looking Recommendations & Release Path

Based on the evidence-derived audit, Model 5 is **ELIGIBLE FOR SHADOW TESTING ONLY UNDER ASYNCHRONOUS OR PRECOMPUTED ARCHITECTURES**. It is **NOT** ready for direct, synchronous in-line CPU deployment.

### Concrete Remediation Roadmap

1. **Precomputed Embedding Architecture (Resolves Gate 5 & Gate 6):**
   - Candidate resumes and job descriptions should be embedded at upload/indexing time via an asynchronous worker pool and cached in a vector store.
   - During live match requests, fetch precomputed 384-dimensional embeddings and compute the Hadamard/cosine product alongside lightweight domain regexes.
   - This reduces live latency from **374 ms to 4.47 ms** and eliminates the need to load PyTorch/transformers in the web serving process.
2. **Post-Hoc Probability Calibration (Resolves Gate 7):**
   - Fit a temperature scaling parameter ($T$) or isotonic regression calibrator on held-out validation logits.
   - Target bringing ECE below 0.10 and Normalized Brier below 0.30 prior to exposing match probability scores to recruiters.
3. **Contradictory Duplicate Cleaning:**
   - Adjudicate or split the conflicting labels for pair `R_9ec670d617d35247__J_78a2a1e24cb08975` in the benchmark repository to prevent artificial test noise.
4. **Controlled Shadow Deployment:**
   - Deploy Model 5 in shadow mode alongside the production pipeline to log real-world ranking scores without impacting production recruiter workflows.
